# Exemple de endpoints.txt — copiez ce fichier en endpoints.txt, à côté du
# binaire termdevtools (voir SPEC.md §3.2 et §9.1), pour ajuster la liste
# d'endpoints proposée par l'auto-complétion (Tab, panneau gauche) à votre
# version d'Elasticsearch, sans recompiler.
#
# Un endpoint par ligne. Les lignes vides et celles commençant par # sont
# ignorées. Si ce fichier est présent (et non vide une fois les commentaires
# retirés), il remplace entièrement la liste par défaut intégrée au binaire.
#
# Liste ci-dessous : celle intégrée par défaut, extraite de la spec OpenAPI
# officielle (elastic/elasticsearch-specification, branche 9.5), filtrée aux
# endpoints sans paramètre de chemin (les /{index}/... nécessitent un nom
# d'index réel — non couvert, cf. SPEC.md §7) et aux domaines
# "administration de base" : _cat (toutes les commandes, ?v systématique),
# _cluster, _nodes, index/recherche/snapshot/ILM/SLM/licence. Volontairement
# écartés : ML, sécurité, watcher, transform, rollup, SQL/ES|QL, CCR,
# connectors, inference, enrich — hors du périmètre admin de base de cet
# outil. À élaguer, compléter ou réécrire entièrement selon vos besoins.
